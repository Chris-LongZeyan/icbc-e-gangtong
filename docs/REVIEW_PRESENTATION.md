# 对外展示方案建议

状态：展示方式建议；尚未新增导览页或独立演示入口。现有原型已支持免登录、合成案例和手动输入。

## 入口组织

报告提供一个体验主入口，并附一个可直接进入交互演示的链接。两个入口部署于同一站点，共用计算核心。开发仓库保持私有，评委通过报告及网页评估方案。

主入口为产品导览，说明目标用户、分类账本、用途预留与付款试算，配一个简洁的合成示例及实际界面。导览同时说明哪些功能已实现、哪些依赖银行合作。

交互入口提供情景选择，无需登录或分发账号密码。用户中心沿用模拟账户和遮罩卡号，所有数据持续标识为合成数据。报价标明来源、时间及参考性质。

## 建议演示场景

1. 学生：港币80,000元，学费、租金和生活预算已登记，检查可安排额5,000元。
2. 双币购买：人民币10,000元、港币20,000元，购买人民币12,000元商品，试算最小换汇。
3. 付款冲突：为上述账户增加租金预留或到账延迟，观察限制条件及可行性变化。
4. 初职青年：准备工资、押金与房租的合成模板，明确已到账与预计收入的区别。

前三项可沿用现有案例和操作；第四项需补充模板与结果验证。

## 交互要求

进入时展示一个明确任务及关键输入，允许自由探索；提供一键重置和返回导览。各访客的修改彼此隔离，保存状态与重新载入默认案例分别提示。现有案例选择和手动试算可以复用，避免建设两套产品。

展示页面使用少量示例帮助理解；完整的输入与输出验证集中在交互演示。技术证明仍保留在报告，网页作为补充证据。
